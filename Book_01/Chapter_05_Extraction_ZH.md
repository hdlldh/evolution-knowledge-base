## 1. 章节论点

在你能把日程安排好之前，你必须先选定一个指标——"在你能有一个计划之前，你必须先选定一个指标"——因为在
一台单机（你）上，只要你会做完所有任务，任何排序花的总时间都一样，因此顺序只在相对于某个目标时才有意义。
计算机科学为每个目标提供了可证明最优的算法（最早截止日期优先，用以最小化最大延迟；最短处理时间优先——
按"重要性 ÷ 时长"加权——用以缩短待办清单或减债），但有三条更深的真相重塑了这套建议：大多数调度问题在形式
上是**难解的**，所以与你的日历较劲是真的难；切换任务的元工作（"上下文切换"）是一项真实成本，其极端形态
坍缩为"抖动"——全速运转却一事无成；而解药往往是**故意**降低响应性——把中断成批处理（"中断合并"），从而
保护吞吐量。这样看来，拖延往往是对错误问题的一个最优解。

## 2. 核心概念

```
概念名称：单机调度（Single-Machine Scheduling）
定义：为一台处理器要做的一组任务排序——这是最要紧的情形，因为那台单机就是我们自己。
为何重要：在一台机器上，只要你做完所有任务，任何排序花的时间都一样长；因此顺序只在相对于所选指标时
才有意义。
作者如何使用：全章的中心框架，逼出"先选指标"这一课，并组织起随后所有算法。
相关概念：指标选择、最早截止日期优先、最短处理时间优先、权重。
```

```
概念名称：选定一个指标（"把目标明确下来"）
定义：在你能把任何日程称为"最优"之前，先决定你如何计分——这是前置步骤。
为何重要："在你能有一个计划之前，你必须先选定一个指标。"你选哪个指标，直接决定哪个算法最优——而不同的
指标给出的计划确实不同。
作者如何使用：全章的组织原则；也是拖延重解（"对错误问题的一个最优解"）与"依指标而生，依指标而死"的来源。
相关概念：最大延迟、完成时间之和、权重、一块表/两块表。
```

```
概念名称：最早截止日期优先（EDD）
定义：先做截止最早的任务，一路做到截止最晚的。
为何重要：在最小化最大延迟上可证明最优；而令人惊讶的是，任务时长与计划完全无关（你甚至不需要知道它们）。
作者如何使用：第一个单机指标；扩展到服务（按到达顺序服务）、CSA 生鲜，并（经修改后）扩展到优先约束与抢占。
相关概念：最大延迟、摩尔算法、优先约束、抢占。
```

```
概念名称：最短处理时间优先（SPT）与加权 SPT
定义：总是做你能做的最快的任务（不加权），或用每个任务的权重（重要性）除以其时长、按最高"密度"优先
（加权）。
为何重要：SPT 最小化完成时间之和（最快地缩短待办清单）——这个指标是从**局外人视角**框定的，最小化他人集体
的等待，而这正是它在"你自己的总时间已固定"的前提下为何是一个明智目标的原因。加权 SPT 是本章的"万能钥匙"——
最小化加权完成时间之和，并在**某些假设下**最小化另几个加权指标，也是不确定性下最好的通用策略（但请注意：
大多数其他调度指标是难解的，所以这把钥匙并不能开每一扇门）。
作者如何使用：用以为 GTD 两分钟法则、债务雪球法（不加权）vs. 债务雪崩法（加权）、咨询顾问的时薪，以及
动物觅食提供依据。
相关概念：完成时间之和、权重/密度、债务雪崩/雪球、抢占。
```

```
概念名称：权重（重要性）与密度
定义：每个任务的一个重要性值；"密度"是权重除以时长（单位时间的重要性）。
为何重要：得出经验法则"只有当一个任务重要一倍时，才值得为它多花一倍时间去优先处理"，并把债务、时薪、
每次觅食的卡路里统一起来。
作者如何使用：把不加权的 SPT 变成加权的万能钥匙。
相关概念：加权 SPT、债务雪崩、时薪、觅食。
```

```
概念名称：优先约束（Precedence Constraints）
定义：当一个任务必须等另一个完成后才能开始。
为何重要：它们可能逼你把一个不重要的阻塞任务当作最重要的；EDD 易于适应（从后往前建日程），但带优先约束的
SPT 是难解的。
作者如何使用：用以解释优先级反转、火星探路者号的失败、McLay 的勺子，以及 Lenstra 搬家货车的反讽。
相关概念：优先级反转、优先级继承、难解性。
```

```
概念名称：优先级反转与优先级继承
定义：优先级反转——一个低优先级任务占着某资源、阻塞了一个高优先级任务，而中等任务却在运行。优先级继承——
那个阻塞任务临时继承它所阻塞之物的优先级。
为何重要：它表明，即便一心扑在"要事第一"上，也可能产生看起来完全像拖延的东西；而解药是反直觉的（抬高那个
微不足道的阻塞者）。
作者如何使用：诊断并修复火星探路者号；Hedberg 的消防出口笑话。
相关概念：优先约束、"最要紧的 vs. 最不要紧的"、阻塞。
```

```
概念名称：调度的难解性
定义：大多数调度问题都没有能在合理时间内找到最优日程的高效算法。
为何重要：一项调查发现约 7% 的问题状态未知；在已理解的 93% 中，只有 9% 可高效求解，84% 已被证明难解。细微
的改动（加上权重、加上起始时间约束）就能把一个可解问题推入难解。
作者如何使用：用以印证"管理你的日历真的令人不堪重负"，并铺垫那个令人意外的宽慰——不确定性反而能恢复
可解性。
相关概念：抢占、未卜先知作为负担、优先约束。
```

```
概念名称：抢占（Preemption）
定义：中途停下一个任务、切换到另一个的能力。
为何重要：它"戏剧性地改变了局面"——为那些在起始时间固定时难解的问题恢复了高效解，并让 EDD/SPT 即便在
"任务何时到来"不确定时也保持最优（配一条简单的切换规则）。
作者如何使用：说明调度比难解性所暗示的更令人鼓舞，并揭示未卜先知反而可能是负担。
相关概念：上下文切换、EDD/SPT 的抢占版本、不确定性。
```

```
概念名称：上下文切换（元工作）
定义：切换任务的开销——给你的位置做书签、决定下一个做什么、重新载入新任务的状态。这些都不是"真正的工作"。
为何重要：抢占不是免费的；人类以分钟（而非微秒）为单位付出代价，所以每小时被打断超过几次就有可能一事无成。
作者如何使用：为亲抢占的论调降温，并解释抖动；也为"写作即打铁、至少留 90 分钟"这一直觉提供依据。
相关概念：抖动、响应性/吞吐量、中断合并。
```

```
概念名称：抖动（Thrashing）
定义：一个系统全速运转、却基本一事无成，因为它被元工作彻底占据。
为何重要：性能不是逐渐退化——而是"从悬崖上掉下去"。多一个任务就压垮整个系统（超载的杂耍者掉的不是那一个
球，而是全部）。
作者如何使用：为一种可辨认的人类恐慌状态命名；把调度与缓存相连（工作集彼此驱逐），并引出逃脱策略。
相关概念：工作集（缓存）、上下文切换、"更笨地干"、中断合并。
```

```
概念名称：响应性 vs. 吞吐量
定义：你能多快作出反应、与你总体能完成多少之间的张力。
为何重要：一条硬性的响应性保证若不加约束，会把整个时间片都花在上下文切换上；解药是设一个最小时间片——对
任一任务承诺一个下限时长。
作者如何使用：用以为时间盒/番茄工作法辩护，并给出"你需要多有响应性就多有响应性、不必更多"的忠告。
相关概念：最小时间片、中断合并、上下文切换。
```

```
概念名称：中断合并（Interrupt Coalescing）
定义：把中断成批、按固定间隔一起处理，而非逐个处理。
为何重要：本章关键的生产力处方——通过拒绝持续响应来保护吞吐量；邮局免费地把它给了我们。
作者如何使用：付账日、每天只查一次邮件、答疑时间、被平反的每周例会，以及 Knuth 极端的批处理人生。
相关概念：响应性/吞吐量、最小时间片、批处理、勿扰模式。
```

## 3. 核心论点

```
论点：在一台单机上，只要你做完所有任务，任何排序花的总时间都一样。
论点类型：理论性 (Theoretical)
提供的证据：结构性论证，被称为"根本且反直觉"到值得重复一遍。
支持强度：强 (Strong)。依构造为真，也是全章的前提。
```

```
论点：在你能把任何日程称为"最优"之前，你必须先选定一个指标。
论点类型：理论性 (Theoretical) / 规范性 (Prescriptive)
提供的证据：单机调度的第一课；不同指标产出不同的最优算法。
支持强度：强 (Strong)。上一条论点的定义性推论。
```

```
论点：最早截止日期优先在最小化最大延迟上最优，而任务时长与它无关。
论点类型：理论性 (Theoretical)（已证明）
提供的证据：被陈述为最优；服务类比（按到达顺序服务）；那个令人惊讶的推论——你无需知道任务要花多久。
支持强度：强 (Strong)。一个已证明的结论；"时长无关"这一点是真正的意外。
```

```
论点：要最小化迟到/腐烂物品的数量，用摩尔算法。
论点类型：理论性 (Theoretical)
提供的证据：按截止日期排程，一旦落后就回头扔掉已排程中最大的那一项（例如放弃西瓜）。迟到/被扔掉的物品
随后可以任意顺序在最后处理。
支持强度：对等价值物品为强 (Strong)。明确指出：一旦物品有不同的重要性，问题就变得难解。
```

```
论点：最短处理时间优先最小化完成时间之和。
论点类型：理论性 (Theoretical)（已证明）
提供的证据：4 天 + 1 天项目的例子：大的先做 = 客户等 9 天，小的先做 = 6 天，对你而言都是同一周。
支持强度：强 (Strong)。对该指标一个干净的实证推演。
```

```
论点：加权最短处理时间优先——按"权重 ÷ 时长"排序——最小化加权完成时间之和，是一把近乎万能的"钥匙"。
论点类型：理论性 (Theoretical)（已证明）
提供的证据：密度法则（"只有当一个任务重要一倍时，才值得为它多花一倍时间去优先处理"）；商业上换算为时薪；
动物按卡路里/时间觅食；债务雪崩（先还利率最高的）。在某些假设下，它还最小化迟到作业的权重之和及其加权延迟。
支持强度：强 (Strong)。多个领域；多指标最优这一点保留了"在某些假设下"的限定。
```

```
论点：减债——先还利率最高的（雪崩法，加权）以最小化总负担；或先还余额最小的（雪球法，不加权 SPT）以最小化
债务数量。
论点类型：规范性 (Prescriptive) / 阐释性 (Interpretive)
提供的证据：把债务映射到加权 vs. 不加权的 SPT。
支持强度：中等 (Moderate)。映射干净；本章明确指出"实践中哪个更好……仍是一个活跃的争议"，在大众媒体与经济学
研究中皆然。
```

```
论点：拖延往往是对错误问题的一个最优解——为错误的指标制定的一个绝佳策略。
论点类型：阐释性 (Interpretive)
提供的证据：应用图标角标给所有任务同等权重，所以先清掉简单的（不加权 SPT）理性地最小化了可见数字；
《X 档案》里"ping/拒绝服务"的吸血鬼；Rosenbaum 2014 年的"预支延迟"研究（人们把近处的桶一路搬到底，而不是
把远处那个只搬一小段）。
支持强度：中等到强 (Moderate to Strong)。这一重解由角标逻辑与预支延迟研究充分支撑；它是一种解读，而非
主张"所有拖延都最优"。
```

```
论点：一心去做最重要的事，还不够——优先约束可能让一件微不足道的任务成为你必须先做的那件。
论点类型：理论性 (Theoretical) / 阐释性 (Interpretive)
提供的证据：火星探路者号上的优先级反转；"有时最要紧的事，非得等最不要紧的事做完了才能做"；McLay 的勺子；
Lenstra 的货车。
支持强度：强 (Strong)。一个具名、有据的工程失败，加上日常例证。
```

```
论点：大多数调度问题都是难解的。
论点类型：实证性 (Empirical) / 理论性 (Theoretical)
提供的证据：一项近期调查——约 7% 状态未知；在已理解的 93% 中，9% 可高效求解，84% 难解。细微改动（给摩尔算法
加权重；加起始时间约束）就把问题推入难解。
支持强度：强 (Strong)，附本章自己的保留（脚注）：84% 这个数字包含了多机问题，"更像管理一群员工、而非管理你
自己的日历"。
```

```
论点：抢占恢复了可解性，并让 EDD/SPT 即便在起始时间不确定时也保持最优。
论点类型：理论性 (Theoretical)（已证明）
提供的证据：操作性配方是一个"相当直接的修改"——抢占式 EDD：当一个任务到来时，只有它比手头这个截止更早才
切换，否则坚持；抢占式 SPT：只有新任务比当前任务剩余时间更快完成才切换。两者都保持最优，并在不确定性下
保证可能的最佳平均表现。
支持强度：强 (Strong)。被陈述为"不确定性下已证明最优"的结论。
```

```
论点：未卜先知反而可能是负担——事先知道起始时间与时长，可能让最优调度变难解，而随作业到来即时反应则容易
得多计算。
论点类型：理论性 (Theoretical)（反直觉）
提供的证据：那些在线最优的加权 SPT 指标，离线（拥有完全的预知）却变得难解。Jason Fried："把'计划'换成
'猜测'，然后放轻松。"
支持强度：强 (Strong)。一个真正而惊人的结论——这里在线问题比离线问题更容易。
```

```
论点：抢占不是免费的——上下文切换是纯开销（"元工作"），而对人类而言它以分钟、而非微秒计。
论点类型：理论性 (Theoretical) / 实证性 (Empirical)
提供的证据：心理学家已表明任务切换会造成延迟与错误，"以分钟为尺度"（未署名研究）；每小时被打断超过几次
就有可能一事无成。生产力数字则明确是轶事式自述：**一位软件工程师朋友**说他 16 小时的一天比 8 小时的一天
产出高出一倍多；Brian 把写作比作打铁（约 30 分钟只是把金属加热，所以要留 ≥90 分钟）；Pruhs 需要 35 分钟
才进入状态。
支持强度：中等到强 (Moderate to Strong)。心理学被引用（未署名研究）；生产力数字是个人轶事，而非实测。
```

```
论点：抖动——全速用力却一事无成——发生在元工作占据系统时，且性能是骤然坍塌、而非逐渐退化。
论点类型：理论性 (Theoretical)（归于 Denning）
提供的证据：Denning 1960 年代的工作；那个多一个球就掉光一切的杂耍者；"多出一个程序就导致了服务的彻底
崩溃"；调度与缓存相遇（工作集彼此驱逐；Zijlstra："上下文切换会让所有缓存失效"）。
支持强度：强 (Strong)。一个具名、奠基性的结论，配有生动的机制。
```

```
论点：要逃出抖动，你可以增加容量、学会说不，或"更笨地干"。
论点类型：规范性 (Prescriptive)
提供的证据：Denning——多加内存，或在没有内存装下某作业的工作集时拒绝它。当两者都做不到时，更笨地干：在
n 封邮件的收件箱里反复扫找最重要的一封是 O(n²)（满三倍 → 慢九倍），所以在抖动状态下，就按随机/屏幕上的
顺序回复。Linux 把它的调度器换成了一个"更笨但更快"的。
支持强度：强 (Strong)。O(n²) 这一点直接接上第 3 章的排序理论；Linux 的例子很具体。
```

```
论点：过度切换的解药是一个最小时间片外加故意的低响应。
论点类型：规范性 (Prescriptive)
提供的证据：操作系统调度器设一个最小时间片（Linux 约 0.75 毫秒；人类"至少几分钟"），使上下文切换永远无法
成为唯一的活动；时间盒/番茄工作法体现了它；"你需要多有响应性就多有响应性、不必更多"。
支持强度：强 (Strong)。一个从机器到人的直接迁移，配有具体机制。
```

```
论点：中断合并——按固定间隔成批处理中断——保护吞吐量。
论点类型：规范性 (Prescriptive)
提供的证据：在一个"付账日"付清所有账单（若无一账单在 31 天内到期）；每天只查一次邮件（若无一封需在 24
小时内回复）；答疑时间；被平反的每周例会；邮局免费地给你合并；Norvig 把三趟分开进城的差事称为"你算法里的
一个单行 bug"；Knuth 极端的批处理（1990 年起就没有邮箱；TeX 每六年调优一次；信件每三个月看一次，传真每六
个月）。
支持强度：强 (Strong)。一整套具体、可迁移的实践。
```

## 4. 框架、模型与思维模型

```
名称：约翰逊法则（两机调度）
描述：对于必须先过机器 A、再过机器 B 的作业（装订；洗衣机→烘干机），最小化总时间。
组成部分：每个作业在每台机器上的用时；一个从两端向内构建的日程。
运作方式：找出所有作业中最短的那一步；若它在第一台机器上，就把该作业排在最前；若在第二台，就排在最后。
重复，从两端向中间推进。这最大化了重叠（两台机器同时运转）。"从最轻的一洗开始，以最小的一篮结束。"
适用时机：两阶段流水线。
局限：只限两台机器；本章转向单机，因为"最要紧的那台机器是我们自己"。
```

```
名称：最早截止日期优先（EDD）
描述：按截止日期从早到晚给任务排程。
组成部分：只需截止日期（时长无关）。
运作方式：最小化任一任务的最大延迟。带优先约束时，从后往前建：在没有任何任务依赖的那些任务中，把截止最晚
的排在最后，然后重复。抢占版本：当一个任务到来、且比手头这个截止更早时，切换。
适用时机：当你在乎的是最坏情况延迟时（绩效评估、最长的客户等待）。
局限：只优化最大延迟；对其余一切迟到多少漠不关心。
```

```
名称：摩尔算法
描述：最小化迟到（或腐烂）物品的数量。
组成部分：截止/腐烂日期；物品时长。
运作方式：按截止日期排程；一旦下一件无法及时完成，就回头扔掉已排程中最大的那一项。重复，直到剩下的都能
排下。被扔掉的物品最后处理、任意顺序（反正都已迟到）。
适用时机：当迟到物品的数量比其严重程度更要紧时（CSA 生鲜；某些官僚情境）。
局限：假定等价值；一旦物品有不同的重要性就变难解。
```

```
名称：最短处理时间优先（SPT）/ 加权 SPT
描述：先做最快的任务（不加权），或按"权重 ÷ 时长"排序（加权）。
组成部分：时长；可选的权重（重要性、金钱、卡路里）。
运作方式：不加权 SPT 最小化完成时间之和（最快地缩短待办清单）。加权 SPT 最小化加权完成时间之和，并在某些
假设下最小化另几个加权指标——那把"万能钥匙"。抢占版本：若新作业的"权重/剩余时间"密度胜过当前作业，就切换。
适用时机：清理积压；债务；觅食；不确定性下最好的通用策略。
局限：带优先约束的 SPT 是难解的；不加权 SPT 会把真正重要的长任务边缘化。
```

```
名称：优先级继承（优先级反转的解药）
描述：当一个低优先级任务阻塞了一个高优先级任务时，阻塞者临时继承那个高优先级。
组成部分：一个被阻塞的高优先级任务；一个阻塞的低优先级任务；一个共享资源。
运作方式：抬高阻塞者，让它得以完成并释放资源，从而为重要任务解除阻塞——而不是让中等任务在最高优先级挨饿
时运行。
适用时机：任何任务争抢共享资源的系统（实时系统；家庭）。
局限：需要检测出阻塞关系；更深的教训是"最要紧 vs. 最不要紧"并不总是一个有效的排序。
```

```
名称：中断合并 + 最小时间片
描述：按固定间隔成批处理中断，并对任一任务承诺一个下限时长。
组成部分：一个周期；一个最小时间片；一个固定的签到间隔。
运作方式：最小时间片防止上下文切换成为唯一的活动；合并把许多小中断变成一次排定的批处理（付账日、每天一次
邮件、答疑时间、每周例会）。
适用时机：异质的短任务流；保护深度工作。
局限：按设计降低了响应性；要求没有任何事需要比该间隔更快的响应。
```

## 5. 研究与证据

```
研究：第一个最优调度算法
研究者：Selmer Johnson（兰德公司）
年份：1954
研究问题：让作业依次通过两台机器（装订：先印后订；洗衣：先洗后烘）的最佳排序是什么？
方法：数学分析。
主要发现：若最短的一步在第一台机器上就先做，在第二台就最后做；从两端向内推进。这最大化重叠、最小化总时间
——调度的第一个最优算法。但该论文**更深**的意义是超越洗衣规则的两个元要点：调度竟然可以用算法表达，以及
最优解**存在**——这正是它"开启了一片庞大文献"、把调度变成一门可解科学的原因。
作者如何使用：说明调度可以用算法表达、且最优解存在，从而开启整个领域。
重要局限：仅限两机情形。
提及的重复验证或争议：无；开启了一片"庞大文献"。
```

```
研究：科学管理与计划板
研究者：Frederick Taylor（米德维尔钢铁）；Henry Gantt（甘特图）
年份：Taylor 自 1874 年起；甘特图于 1910 年代
研究问题：如何用好机器与人的时间？
方法：工业实践——一块显示每台机器当前与等待任务的公告板；后来的甘特图。
主要发现：调度可以被赋予视觉/概念形态（用于胡佛大坝、州际公路系统；至今仍在亚马逊、宜家、SpaceX）——但
Taylor 与 Gantt 并未解决"哪种日程最优"。
作者如何使用：调度科学在 Johnson 使其可解之前的史前史。
重要局限：描述性/组织性的，而非优化。
提及的重复验证或争议：未发现。
```

```
研究：调度中的优先约束与难解性
研究者：Eugene "Gene" Lawler（伯克利），与 Jan Karel Lenstra 等
年份：Lawler 的"带优先约束 EDD"结论 1968；地形测绘工作自 1970 年代起
研究问题：优先约束如何影响最优调度？哪些问题可解？
方法：算法设计与复杂性分析。
主要发现：带优先约束的 EDD 易解（从后往前建），但带优先约束的 SPT 难解；即便细微改动也会把问题推过可解/
难解的界线。
作者如何使用：确立调度理论的"砖墙"，并引出 Lawler（他自己的人生提供了一个优先级反转的轶事）。
重要局限："难解"在此定义较松；细致处理留待第 8 章。
提及的重复验证或争议：Lawler 1994 年去世后，ACM 以他的名字设立了一个人道主义奖。
```

```
研究：调度问题复杂性的调查
研究者：未提及（"一项近期调查"）。
年份：未提及。
研究问题：多大比例的调度问题是可解的？
方法：对已知调度问题的调查/分类。
主要发现：约 7% 的问题状态未知；在已理解的 93% 中，只有 9% 可高效求解，84% 已被证明难解。

提及的重复验证或争议：未发现。

```
研究：火星探路者号的优先级反转失败
研究者：喷气推进实验室（JPL）工程师；软件负责人 Glenn Reeves
年份：1997
研究问题：不适用——一起真实的工程事故。
方法：对一艘 1.5 亿美元航天器的诊断与远程打补丁。
主要发现：探路者号反复重启，因为它最高优先级的任务（信息总线）被一个低优先级任务阻塞，而中等优先级任务却

提及的重复验证或争议：脚注的反讽——Reeves 把这个 bug 归咎于"截止期压力"，以及修复它一事本身被判为"较低
优先级"，因此根本原因恰好映照了问题本身。

```
研究：预支延迟的水桶实验
研究者：David Rosenbaum 及同事（宾州州立大学）
年份：2014
研究问题：人们是否会为尽快完成子目标而不惜多花体力？

作者如何使用：把拖延重解为在优化错误的指标（减少未完成子目标的数量），而非懒惰。
重要局限：单一走廊任务；推广到拖延是作者的阐释性延伸。

```

## 6. 实验

```
实验名称：Rosenbaum 的预支延迟走廊任务
设置：走廊里两个重桶——一个在参与者身边，一个在朝目标端走一段的位置。
参与者：人类参与者（人数未提及），宾州州立，2014。
流程：把两个桶之一搬到远端。
结果：人们压倒性地抓起近处的桶、把它搬了全程，途中经过那个本可只搬一小段的更远的桶。
解释：一种"预支延迟"倾向——即便要多花体力也要加速完成子目标——作者把它映射到"把拖延当作在优化未完成任务
的数量"。
它证明了什么：减少未完成子目标数量的冲动，可以压过整体效率。
可能的替代解释：抓近处的桶可能是在减少工作记忆负荷（少追踪一件事），而非反映"急于完成子目标"；那份体力
代价可能是被低估、而非被明知地接受。
```

```
实验名称：多道程序的崩溃（抖动）
设置：一台运行数量递增的并发作业的共享内存计算机。
参与者：不适用——一种系统现象。
流程：逐个把作业加入多道程序组合。
结果：越过某个不可预测的临界阈值，再加一个作业就导致服务的骤然彻底崩溃，而非逐渐变慢。
解释：工作集彼此驱逐，系统把全部时间花在换内存、而非干活上——抖动。
它证明了什么：过载的失败是一道悬崖、而非一个斜坡，在机器上、以及（类比地）在心智上皆然。
可能的替代解释：那个阈值取决于具体的内存/工作集大小；人类类比是示意性的，而非被测量的等价。
```

## 7. 案例与故事

```
案例标题：时间管理相互矛盾的福音书
人物 / 组织：《搞定》；《吃掉那只青蛙》；《拖延心理学》；威廉·詹姆斯；Frank Partnoy 的《慢决策》
背景：时间管理指南长盛不衰的畅销地位，而它们的建议"相互分歧、彼此不一"。
经过：《搞定》说任何两分钟以内的任务立刻做；《吃掉那只青蛙》说从最难的开始；《拖延心理学》说先排休闲、再用
工作填空；威廉·詹姆斯说"没有什么比一件未完成任务的永恒悬挂更令人疲惫"；Partnoy 则主张故意不立刻去做。
结果："每位大师都有一套不同的系统，很难知道该听谁的"——正是本章"先选指标"的框架所化解的问题（每位大师都在
优化一个不同的指标）。
所阐释的概念：为何你必须先选指标；不同指标 → 不同的最优建议。
此案例为何有用：即刻可共鸣；为整章定框，并展示计算机科学对一场自助类的论战作出裁决。
复用潜力：高 (High)
```

```
案例标题：泰勒的板与甘特的图
人物 / 组织：Frederick Taylor（米德维尔钢铁）；Henry Gantt
背景：调度作为一门学科在工业革命中的诞生。
经过：Taylor 于 1874 年放弃哈佛去当机械学徒，一路升到总工程师，发明了"科学管理"，其核心是一块显示每台机器
当前与等待任务的计划板。Gantt 把它变成了甘特图（1910 年代），用于胡佛大坝与州际公路系统，至今仍挂在亚马逊、
宜家、SpaceX 的墙上。
结果：调度获得了视觉与概念形态——但还没有一种方法能知道哪种日程最优。
所阐释的概念：调度作为研究对象；优化之前的史前史。
此案例为何有用：一个利落的起源故事，把 19 世纪的机械车间与现代项目管理连在一起。
复用潜力：高 (High)
```

```
案例标题：约翰逊的洗衣
人物 / 组织：Selmer Johnson（兰德公司）
背景：第一个可解的调度问题，被框定为两台依次的机器。
经过：对于必须先洗后烘的一批衣物，Johnson 证明你应从洗涤时间最短的那一批开始、以烘干时间最短的那一批结束，
向内推进——最大化"两台机器同时运转"时的重叠。
结果：调度的第一个最优算法（1954）："从最轻的一洗开始，以最小的一篮结束。"
所阐释的概念：两机调度；重叠最大化。
此案例为何有用：一件人人熟悉的家务被严谨化；一条干净、好记的规则。
复用潜力：高 (High)
```

```
案例标题：拖延的火星探路者号
人物 / 组织：NASA/JPL；软件负责人 Glenn Reeves
背景：1997 年夏——人类第一辆火星车，一艘穿越了 3.09 亿英里的 1.5 亿美元航天器。
经过：探路者号开始忽略它最高优先级的任务（信息总线）、转而做中等的活儿，随后自我重启，损失了将近一天——
两次。JPL 诊断出一个经典的优先级反转：一个低优先级任务占着资源、阻塞了高优先级任务，而中等优先级任务却在
运行。他们隔着整个太阳系发送了一个补丁：优先级继承。
结果：火星车恢复了。脚注的反讽：Reeves 把这个 bug 归咎于"截止期压力"，以及修复它一事被判为"较低优先级"——
根本原因映照了问题本身。
所阐释的概念：优先级反转；优先级继承；为何"要事第一"会看起来像拖延。
此案例为何有用：高风险、戏剧化、全球瞩目，还带一个完美的自指转折；本章的招牌案例。
复用潜力：高 (High)
```

```
案例标题：Mitch Hedberg 与消防出口
人物 / 组织：喜剧演员 Mitch Hedberg
背景：一个恰好编码了优先级反转与继承的笑话。
经过：一名保安叫 Hedberg 让开，因为他"挡住了消防出口"。Hedberg："搞得好像真着火了我还不跑似的……如果你
易燃、又有腿，你永远不会挡住消防出口。"
结果：保安的担心是优先级反转；Hedberg 的反驳是优先级继承（一群冲过来的人会让你很快继承他们的优先级）。
所阐释的概念：一个笑话里的优先级继承。
此案例为何有用：为一个抽象的系统概念提供了一个好记、好笑的助记。
复用潜力：高 (High)
```

```
案例标题：McLay 的勺子与 Lenstra 的搬家货车
人物 / 组织：Laura Albert McLay（运筹学）；Jan Karel Lenstra；Eugene Lawler
背景：日常中的优先约束。
经过：McLay 带着三个孩子过日子，她指出：不让孩子吃早饭就出不了门，而不记得拿勺子孩子就吃不上饭——"你忘掉的
某件极简单的事，就能拖住一切"。1978 年 Lenstra 帮朋友 Gene 搬家：他们要还一辆货车，但要用那辆货车去还设备，
而设备是用来修公寓的；那件不急的公寓维修，其实才是最急的。美妙的反讽：Gene 就是 Eugene Lawler，那个世纪
最伟大的优先约束专家。
结果：说出那个阻塞性的前提、并让它动起来，就是把事情办成的方法。
所阐释的概念：优先约束；日常生活中的优先级反转。
此案例为何有用：亲切、好笑，让一个抽象约束立刻可用；Lawler 的反讽是额外彩蛋。
复用潜力：高 (High)
```

```
案例标题：《X 档案》的吸血鬼与拒绝服务攻击
人物 / 组织：《X 档案》（Mulder）
背景：拖延作为一种系统漏洞利用。
经过：卧床的 Mulder 眼看要被一个有强迫症的吸血鬼吃掉，撒了一地葵花籽；吸血鬼强迫性地一颗一颗捡，直到天亮
救了 Mulder。
结果：一次"ping 攻击"/拒绝服务：用琐碎任务淹没一个系统，重要的那件就丢失了。
所阐释的概念：一堆小任务如何让重要任务挨饿；因过载而拖延。
此案例为何有用：对拒绝服务/优先级饥饿的一个生动的流行文化例证。
复用潜力：高 (High)
```

```

## 8. 最佳教学示例

```
概念：在一台单机上，顺序无关紧要
示例：如果你会在一台机器上做完所有任务，任何排序花的总时间都一样——所以顺序只在相对于某个指标时才有意义。
为何有效：一个"根本且反直觉"的事实，瞬间为整个"先选指标"的纲领提供了正当性。
可迁移领域：数学 (Mathematics)
```

```
概念：完成时间之和（SPT）
示例：一个 4 天与一个 1 天的项目：大的先做让客户等 4+5 = 9 天；小的先做，1+5 = 6 天——对你而言是同一周，
却为他们省了三天。
为何有效：一次微小的算术互换，就让一个抽象指标及其最优规则一目了然。
可迁移领域：商业 (Business)
```

```
概念：加权 SPT / 密度法则
示例："只有当一个任务重要一倍时，才值得为它多花一倍时间去优先处理"——权重 ÷ 时长，最高者优先；顾问干脆用
时薪。
为何有效：把一条证明变成任何人都能用到待办清单或客户清单上的一行启发式。
可迁移领域：商业 (Business)
```

```
概念：优先级反转 / 继承
示例：Hedberg 挡着消防出口——"如果你易燃、又有腿，你永远不会挡住消防出口。"
为何有效：一个笑话在一个画面里同时编码了失败（反转）与解药（继承）。
可迁移领域：日常生活 (Everyday Life)
```

```
概念：优先约束
示例：不让孩子吃早饭你就走不了，而不记得拿勺子孩子就吃不上——于是那把勺子一时间成了家里最重要的东西。
为何有效：一件微不足道的物件（一把勺子）被赋予最高重要性，让抽象约束变得可感。
可迁移领域：日常生活 (Everyday Life)
```

```
概念：抖动
示例：一个杂耍者多接一个球，掉的不是那个球——而是全部；系统"从悬崖上掉下去"。
为何有效：用单个物理画面捕捉了过载崩溃那种骤然而彻底的性质。
可迁移领域：日常生活 (Everyday Life)
```

```
概念：中断合并
示例：在一个"付账日"付清全部五张信用卡账单；每天只查一次邮件；Knuth 每六年一次的 TeX 调优。
为何有效：具体、可采纳的实践，让一项操作系统技术对一个人立刻可行动。
可迁移领域：日常生活 (Everyday Life)
```

## 9. 反直觉洞见

```
洞见：在一台单机上，你做任务的顺序不改变它们花的时间。
常见看法：更好的顺序能让一切更快完成。
作者的论证：如果你会做完所有任务，总时间是固定的；顺序只影响某个指标（延迟、完成时间之和、加权负担），
所以你必须决定你在优化什么。
证据：结构性证明。
为何令人意外：它化解了大多数时间管理建议的前提，把整个问题移到了"指标选择"上。
```

```
洞见：为了最小化最大延迟，每个任务花多久完全无关紧要。
常见看法：你需要估计任务时长才能把计划做好。
作者的论证：最早截止日期优先仅凭截止日期就能在最大延迟上最优——你甚至不需要知道时长。
证据：EDD 的最优性结论。
为何令人意外：一个人人以为必不可少的关键输入，在这个目标下竟是不必要的。
```

```
洞见：拖延可以是一个最优解——对错误问题的最优解。
常见看法：拖延是懒惰或一个坏掉的策略。
作者的论证：先清掉许多琐碎任务（不加权 SPT）最优地最小化了未完成项的数量——为你本无意选择的一个指标
（任务计数）制定的绝佳策略；应用角标与预支延迟把我们推向它。
证据：角标逻辑；Rosenbaum 的水桶研究；《X 档案》的拒绝服务。
为何令人意外：它把一种道德失败，重构为一个瞄准了错误目标的理性算法。
```

```
洞见：先做最重要的事，也可能看起来完全像拖延。
常见看法：永远攻击最高优先级的任务就不会出错（歌德："最要紧的事，绝不能受制于最不要紧的事"）。
作者的论证：优先约束与优先级反转意味着最重要的任务可能被一件微不足道的任务阻塞，所以有时你必须把那个
微不足道的阻塞者当作最重要的。
证据：火星探路者号；McLay 的勺子；Lenstra 的货车。
为何令人意外：它证伪了一句备受尊崇的箴言，并在特定情形下颠倒了"要事第一"的规则。
```

```
洞见：未卜先知反而可能是负担——知道未来可能让调度更难、而非更易。
常见看法：越有预知，计划越好。
作者的论证：有几个指标在离线（拥有起始时间与时长的完全知识）时难以优化，却有高效的最优在线策略（随作业
到来即时反应）。
证据：离线难解/在线可解的对照；Jason Fried 的"把'计划'换成'猜测'"。
为何令人意外：不确定性通常是障碍，在这里却让问题在计算上更容易。
```

```
洞见：全速用力可能一事无成。
常见看法：最大努力产出最大成果。
作者的论证：当元工作占据系统时，它会抖动——全力运转而真正的工作降到零，且是骤然坍塌、而非逐渐退化。
证据：Denning 的多道程序崩溃；那个超载的杂耍者。
为何令人意外：努力与产出彻底脱钩，而失败是一道悬崖、不是一个斜坡。
```

```
洞见：想完成更多，就故意降低响应性。
常见看法：响应性是美德；要快点回复。
作者的论证：一条硬性的响应性保证会把你全部时间耗在上下文切换上；最小时间片与中断合并保护吞吐量。"你需要
多有响应性就多有响应性、不必更多。"
证据：操作系统的最小时间片；邮局；Knuth；答疑时间。
为何令人意外：生产力的解药是故意延迟与成批，而不是反应更快。
```

## 10. 独特或不寻常的观点

```
观点："在你能有一个计划之前，你必须先选定一个指标。"
为何显得独特：它把时间管理最难的部分从"执行"移到了"目标定义"，并解释了自助大师为何相互矛盾（他们优化的是
不同的指标）。
与其他主题的潜在关联：目标设定；决策论；OKR；"能被衡量的才能被管理"传统。
```

```
观点：拖延是为错误指标而设的一个最优算法。
为何显得独特：它用一个计算性的说法取代了对拖延的道德/心理说法——策略没问题，是目标被设错了。
与其他主题的潜在关联：行为经济学；目标替换；指标博弈（古德哈特定律）。
```

```
观点：未卜先知作为负担（离线比在线更难）。
为何显得独特：它颠倒了信息通常的价值——完全的预知可能让计算变难解，而无知反而让它保持容易。
与其他主题的潜在关联：在线 vs. 离线算法；信息的价值（与代价）；规划 vs. 即兴。
```

```
观点：抖动作为一种被命名的人类状态。
为何显得独特：它为"忙到没空组织自己在忙什么"的那种恐慌，给出了精确的系统词汇，包括它悬崖式的发作。
与其他主题的潜在关联：倦怠；认知负荷；不堪重负；缓存（工作集）。
```

```
观点：中断合并作为一条人生设计原则。
为何显得独特：它把备受尊崇/鄙夷的仪式（每周例会、答疑时间、邮政周期）重构为保护吞吐量的成批处理，并主张我们
的设备应显式地提供它。
与其他主题的潜在关联：深度工作；注意力经济学；通知设计；批处理 vs. 流处理。
```

## 11. 张力、矛盾与开放问题

```
议题：本章把加权 SPT 誉为近乎万能的"钥匙"，可大多数调度问题却是难解的。
作者立场：加权 SPT 对多个指标最优，也是不确定性下最好的通用策略；然而已理解问题的 84% 是难解的。
可能的反驳：这把钥匙的保证只在"某些假设下"、且主要在在线/不确定的情形下成立；读者可能把它过度推广到那些
不存在高效最优的问题上（加权摩尔算法、优先约束+SPT、起始时间约束）。本章两者都说了，却没有清晰划出钥匙
奏效的范围。
何种证据有助于澄清：一张清晰的图，标出现实中哪些调度处境落在可解 vs. 难解的区域。
```

```
议题：拖延是 bug，还是一个最优算法？
作者立场：往往是对错误问题（最小化任务计数）的一个最优解，由角标与预支延迟驱动。
可能的反驳：这有过度合理化真正的回避行为之险；本章承认拖延"同样可能出现在……真诚努力的人身上"，却没有把
"指标错位型拖延"与"由情绪驱动的回避"区分开来，而心理学文献把二者视为不同。
何种证据有助于澄清：把"错误指标"式拖延与情绪调节式回避分开的研究，以及修正指标（例如关掉角标）是否真的
减少了拖延。
```

```
议题：抢占在理论上最优，但在实践中"不是免费的"。
作者立场：抢占式 EDD/SPT 是最优的、并恢复了可解性，但上下文切换对人类要花数分钟、且引发抖动。
可能的反驳：两半彼此抵触——算法上最优的策略（一有更高密度的作业到来就切换）恰恰是产生昂贵上下文切换的
东西；本章自己的建议（最小时间片、合并）是对纯抢占的一次部分退让。那个调和（切换，但不低于一个最小时间片）
被说出来了，但"总切换到更高密度的作业"与"承诺一个最小时间片"之间的张力被留作非正式处理。
何种证据有助于澄清：最优时间片大小作为"切换成本与作业密度方差"的函数——本章指向了它，却没给出面向人类的
公式。
```

```
议题："更笨地干"（按随机顺序回邮件）vs. "做那些有分量的事"。
作者立场：在抖动状态下，用错误的顺序做事也胜过什么都不做；但除此之外你应按权重优先。
可能的反驳：这些是依情形而定的（抖动 vs. 正常），但读者可能把"随机回复"当作一般建议；那条界线——你何时
抖动到"优先排序本身成了瓶颈"——是定性的。
何种证据有助于澄清：一个阈值，标出何时"优先排序的 O(n²) 成本"超过其收益；本章点了机制，却没点触发点。
```

```
议题：债务雪球 vs. 雪崩的争议被承认、却未被解决。
作者立场：雪崩（利率最高）最小化总负担；雪球（余额最小）最小化债务数量；哪个更好"实践中……仍是一个活跃的
争议"。
可能的反驳：本章把这当作一个纯粹的指标选择，但雪球的流行靠的是激励/行为效应（早期胜利带来的势头），而这
完全落在调度模型之外。
何种证据有助于澄清：早期胜利的行为收益是否胜过利息成本——一个本章点出、却未回答的实证问题。
```

```
议题：84% 难解这个数字很戏剧化，却部分是个假象。
作者立场：大多数调度问题难解，所以日历管理真的很难。
可能的反驳：本章自己的脚注承认该数字包含多机问题（"管理一群员工"），所以单机的个人调度，明显没有 84% 所
暗示的那么糟——一条容易被漏掉的保留。
何种证据有助于澄清：仅限单机问题的可解性分解。
```

## 13. 心理学关联

- **拖延与预支延迟。** 本章核心的心理学动作：把拖延重构为在优化任务计数，并引用 Rosenbaum 的预支延迟——那种
  即便要多花成本也要提早完成子目标的相反冲动。
- **目标设定与指标选择。** "先选指标"是一个目标定义问题；关联到目标替换与对生产力的道德化。
- **任务切换与认知负荷。** 人类的上下文切换成本（延迟与错误"以分钟为尺度"）关联到注意力研究与工作记忆
  的限度。
- **不堪重负/倦怠即抖动。** 为"忙到没空组织自己在忙什么"的恐慌给出了精确词汇；那种悬崖式发作映射到骤然的
  倦怠。
- **未完成任务的蔡格尼克式张力。** 威廉·詹姆斯的"没有什么比一件未完成任务的永恒悬挂更令人疲惫"，以及未完成
  项那种被感知的"重量"，关联到蔡格尼克效应（推断；未点名）。
- **减债中的动机。** 雪球法的流行靠的是早期胜利的势头——一种落在调度数学之外的行为/动机效应。
- **界面驱动的行为。** 应用角标强加了一个隐含的等权重指标——一个选择架构与助推塑造我们行为的案例。本章那条
  "界面虚伪"的脚注让这一点更锋利：界面向用户索取注意力的方式，是 CPU 对自身部件绝不会容忍的。
- **调度者即被调度者。** 对人（与操作系统）而言，做规划的那台机器与被规划的那台是同一台——所以"把待办清单
  理顺，本身就是待办清单上的一项"。规划与执行争夺同一份有限资源，是不堪重负背后一种独特的自指。
- **节律所要求的最小响应。** 邮政系统以两种方式给了我们中断合并：你至多每天被打断一次，**并且**那 24 小时的
  节律要求极低的响应性——你在收信后五分钟还是五小时回复，毫无区别。这是设计"低响应容忍型"日常的一条线索。

## 14. 数学与决策科学关联

- **调度理论 / 运筹学。** 本章是对经典单机调度结论的一次巡礼（Johnson、EDD、Moore、SPT、加权 SPT）。
- **计算复杂性 / 难解性。** 可解 vs. 难解的版图（9% vs. 84%），并前瞻至第 8 章；细微改动翻转复杂性类别。
- **在线 vs. 离线算法。** "未卜先知是负担"正是在线/离线之分——而且是罕见的一例：在线问题反而是更容易的那个。
- **优化指标。** 最大延迟、（加权）完成时间之和、迟到作业数量——每个都是一个各有其最优的独立目标，说明"最优"
  离开目标就毫无意义。
- **比率/贪心启发式。** 权重 ÷ 时长（密度）是一条贪心比率规则，在债务雪崩与最优觅食的卡路里/时间中都有映照。
- **实时系统理论。** 优先级反转/继承、响应性/吞吐量、最小时间片，都是实时调度的核心概念。
- **与缓存（第 4 章）、排序（第 3 章）的关联。** 抖动是一个工作集/缓存现象；反复扫描收件箱的 O(n²) 成本，是
  排序理论被用到注意力上。

## 15. 体育关联

**书中的直接示例：** 未发现。（出现了动物觅食，但没有体育。）

**推断出的应用（本人推断）：**
- **场上时钟与换人调度。** 一位换人名额固定、时钟在走的教练，面对的是抢占下的单机调度问题——只有当替补的
  "密度"（每剩余分钟的影响）胜过场上球员时才换，恰恰是加权 SPT 的切换规则。
- **训练负荷周期化作为优先约束。** 有些适应必须等另一些巩固后才能开始（先打基础体能，再练速度）；排错顺序
  就是一次优先级反转，会像 McLay 的勺子那样卡住整个训练块。
- **赛程拥堵即抖动。** 一家俱乐部在联赛、杯赛、洲际赛之间越过阈值地周旋，就可能"掉光一切"——阵容疲劳会让
  所有赛事的成绩一起骤然坍塌，而非逐渐下滑，正是那个超载的杂耍者。
- **恢复窗口作为最小时间片/中断合并。** 保护一个不受打断的恢复下限（并把媒体/商业义务成批到固定窗口），是把
  时间盒用到运动员的吞吐量上。
- **休息 vs. 生锈即响应性/吞吐量。** 让主力休息（一个赛季的吞吐量）与保持比赛状态（响应性）之间存在权衡——
  同一个取舍，而"你需要多有响应性就多有响应性、不必更多"的忠告支持轮换。

## 16. 人工智能与机器学习关联

**书中直接内容：** 操作系统调度器、线程、上下文切换、Linux 调度器（被换成一个"更笨但更快"的），以及 Denning
的多道程序/抖动工作，都是本章所描述的核心系统素材。

**推断出的关联（本人推断）：**
- **LLM 智能体的任务调度。** 一个在子任务间周旋的智能体面对的是单机调度：加权 SPT（价值 ÷ 预期步数）是给
  工具调用或子目标排序的一个有力默认策略，而"未卜先知是负担"警告人们在环境不确定时不要过度规划。
- **上下文切换 = KV 缓存/上下文重载。** 让一个智能体在任务间切换会让它的工作上下文失效（Zijlstra 的"上下文
  切换让所有缓存失效"），这是把相关子任务成批的论据——面向智能体的中断合并。
- **抖动即过度并行。** 生成过多争抢共享内存或速率限制的并发智能体/线程，会让吞吐量骤然坍塌——那个多道程序的
  悬崖，被用到多智能体系统上。
- **推理服务：响应性 vs. 吞吐量。** 模型服务中的批大小正是最小时间片/延迟 vs. 吞吐量的取舍；更大的批以牺牲
  响应性为代价提高吞吐量。
- **奖励/指标设定错误。** "拖延是在优化错误指标"就是强化学习中的奖励攻击/古德哈特问题：一个完美地优化了一个
  糟糕目标的智能体，看起来很病态。
- **在线调度与遗憾。** 不确定性下的抢占式 EDD/SPT 是具有平均情况最优性的在线算法——与第 2 章的老虎机/遗憾
  素材属同一族。

标题：先选指标，再谈计划
类型：洞见 (Insight)
摘要：在一台单机上，只要你做完所有任务，任何排序花的总时间都一样——所以顺序只在相对于某个目标时才有意义。

```
CARD ID: B01-C05-02
标题：约翰逊法则（两机调度）
类型：模型 (Model)
摘要：Selmer Johnson（1954），第一个最优调度算法：对于先过机器 A、再过 B 的作业（洗衣：洗→烘），若最短的

## 19. 跨书对比章节摘要

```
主要论点：好的调度始于选定一个指标，因为在一台单机（你）上，把你所有任务的任何排序花的总时间都一样。计算机
科学为每个指标给出可证明最优的算法——用最早截止日期优先应对最大延迟，用最短处理时间优先（按重要性 ÷ 时长
加权）应对待办清单——但大多数调度问题难解，切换任务的元工作（"上下文切换"）是一项真实成本、极端时变成
"抖动"，而解药往往是通过把中断成批（"中断合并"）来故意降低响应性。拖延往往是对错误问题的一个最优解。

前五大概念：
1. 先选指标（单机调度）
2. 最早截止日期优先（最大延迟）与最短/加权处理时间优先（那把"万能钥匙"）
3. 优先约束、优先级反转与优先级继承
4. 大多数调度问题的难解性；抢占与"未卜先知作为负担"
5. 上下文切换 → 抖动 → 中断合并/最小时间片

前三大论点：
1. 在一台机器上任何排序花的时间都一样长，所以在任何日程能被称为"最优"之前，你必须先选一个指标。
2. 加权 SPT（权重 ÷ 时长）是一个近乎万能的最优策略、也是不确定性下最好的默认；然而已理解的调度问题中 84%
   难解。
3. 抢占不是免费的——上下文切换是真实开销，会坍缩为抖动，可用最小时间片与中断合并来治。

前三大案例：
1. 火星探路者号的优先级反转（及其自指的"较低优先级"bug）
2. 高德纳批处理、自 1990 年起无邮箱的人生（把中断合并推到极端）
3. 相互矛盾的时间管理畅销书，被"先选指标"所化解

前三大研究：
1. Selmer Johnson（1954）——第一个最优调度算法
2. Rosenbaum 等（2014）——预支延迟（即便多花成本也要加速完成子目标）
3. Peter Denning（1960 年代）——抖动/多道程序崩溃

最独特的观点：未卜先知反而可能是负担——有几个调度指标在拥有完全预知时难以优化、在线却容易，所以"无知加即时
反应"胜过规划；"把'计划'换成'猜测'"。

最反直觉的观点：拖延往往是为错误指标而设的一个最优算法（并且与之相关，一心扑在"要事第一"上，也可能通过
优先级反转看起来完全像拖延）。

最大的弱点或开放问题：本章把加权 SPT 誉为"万能钥匙"、把抢占誉为最优，同时又承认 84% 难解、以及上下文切换让
抢占变得昂贵——却没有清晰划出钥匙奏效的范围，也没有化解"总切换到更高密度的作业"与"承诺一个最小时间片"之间
的张力；它点出、却没有解决"债务雪球 vs. 雪崩"以及"拖延是指标问题还是情绪问题"这两处争议。

最佳内容机会：一期以"拖延是在优化错误指标"为主轴的长视频——应用角标、预支延迟、《X 档案》的拒绝服务吸血鬼
——落点在"先选指标"以及古德哈特/奖励攻击的平行。
```
